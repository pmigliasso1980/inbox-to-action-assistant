# Repository Guide — System of Record

This is the authoritative starting point for a fresh contributor or coding
agent. The repository is a course-spanning laboratory, so many reports are valid
historical evidence without describing the current default architecture.

## Authority order

When documents disagree, use this order:

1. Executable tests and typed code contracts.
2. Accepted ADRs indexed in `docs/DECISIONS.md`.
3. Generated evidence under `reports/` and `runs/`.
4. Topic documentation beside the relevant code.
5. Module reports and older README sections as historical evidence.

Never rewrite historical measurements merely to match a newer decision.

## What this repository is

It contains four related bodies of work:

- a frozen Python code-review evaluation used across Modules 1–10;
- a typed provenance graph and bounded agent orchestration architecture;
- a separate incident post-mortem capstone proving cross-session graph value;
- MCP teaching examples and an inbox workflow-design prototype.

The project is not one production service with a single CLI. Each evaluated
system has its own documented entry point.

## Verified entry points

| Goal | Command or document |
|---|---|
| Run all repository checks | `python3 -m pytest -q` |
| Run incident capstone | `python3 capstone_incident/run.py` |
| Reproduce harness ablation | `python3 experiments/harness_ablation/run_experiment.py` |
| Inspect production dashboard | `reports/dashboard.md` |
| Refresh readiness telemetry | commands in `reports/README.md` |
| Inspect graph guarantees | `graph/README.md` and `graph/test_store.py` |

The README sections describing `src.inbox_action` and Module 4 are historical
course/product records. They are not the verification entry point for the
current graph and capstone work.

## Current architectural decisions

- Default review path: deterministic gates before expensive evaluation.
- Planning: removed from the default path; route only dependency-bearing work.
- Multi-agent context: bounded summaries or graph queries, never transcripts.
- Graph: SQLite locally; PostgreSQL is the production target.
- Graph history: additive claims and `supersedes`, not destructive overwrite.
- Provenance: every claim must link to a source with a verbatim span.
- Artifact content: keep large artifact bodies outside the graph.
- Model spend: offline/frozen replay by default; live calls require authorization.
- External actions: human approval and audited adapters are required.

See `docs/DECISIONS.md` for status and evidence links.

## Where knowledge belongs

- Cross-cutting contributor rules: root `AGENTS.md`.
- A component's invariants and operations: its adjacent `README.md`.
- A durable architecture choice: an ADR plus the decision index.
- Reproducible measurements: generated JSON/JSONL under `runs/`.
- Human-readable measurement synthesis: generated or evidence-linked reports.
- Temporary experiment control flow: typed handoffs, not durable graph facts.

## Fresh Session Test

The reproducible scorecard is generated by:

```bash
python3 evals/fresh_session_test.py
```

It checks whether a reader starting only from the README and `AGENTS.md` can
locate current answers without relying on conversation history. The before
snapshot is commit `2c3ce3f`; results and methodology are in
`docs/FRESH_SESSION_SCORECARD.md` and `docs/KNOWLEDGE_VISIBILITY.md`.
