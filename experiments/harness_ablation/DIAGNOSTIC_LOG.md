## Specific observations

The bare output was short but spent its entire error budget on guesswork: it inferred escalation semantics, accepted unknown enums, and treated whitespace as data. The full harness eliminated those guesses by showing strict Pydantic-style boundaries and the exact focused verification command. Its single diagnostic cycle converted the contract into executable feedback.

The ablated output retained the correct escalation decision tree, so repository context alone improved the score from 50% to 62.5%. Removing verification still lost three boundary cases. Restoring executable verification added the remaining 37.5 percentage points and reached 100%.

Executable feedback added only +0.0060 ms of measured harness runtime versus bare while recovering four checks. Ablation saved 0.0090 ms but lost three checks; runtime savings were immaterial compared with the quality drop.

Measured verification runtime is reported only as test execution time; no unsupported claim is made about model thinking time or token use. New API cost was $0.

## Ablation impact

Ablating verification reduced pass rate from 100% to 62.5% (-37.5 points). The failures cluster at boundaries rather than core logic, demonstrating that the subsystem's value is not more code—it is making fail-closed behavior observable before submission.

## Method limitation

These are three captured outputs produced in one controlled coding-agent session under explicit context profiles, not three statistically independent model trials. The experiment supports attribution for this task and repository; it does not estimate population-level model performance. Repeating with randomized fresh sessions would be the next stronger design.
